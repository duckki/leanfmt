# leanfmt 1.0.0

## Changes

This release establishes the [1.0 stability policy](../stability.md) for
formatting output, the CLI, the public library API, and supported Lean versions.
It updates the release status and clarifies the safety checks' limits.

The formatter implementation, parser, dependencies, Lean 4.36.0 development
toolchain, and formatting defaults are unchanged from v0.4.8. The package
version changes from 0.4.8 to 1.0.0. Projects already formatted with v0.4.8
should see no formatting changes under the same toolchain and options.

## External validation baseline

The complete v0.4.8 external gate finished on November 19, 2026. The validated
release is [`6c38dda951b42a314e64010d6a3d031da77002ef`](https://github.com/duckki/leanfmt/commit/6c38dda951b42a314e64010d6a3d031da77002ef).
This documentation and version-only preparation carries forward that evidence;
it is not a new external validation run.

All 10,826 checked files passed preservation, actionable-overflow, fallback,
and independent idempotency diagnostics. Mathlib additionally passed missing-rule
checks. Initial builds, changed-module builds where sources changed, and complete
post-format builds passed for all four projects.

The gate used fresh upstream checkouts: the matching v4.36.0 tags for Mathlib
and CSLib, and the recorded `main` revisions for Flare and GraphQL. Mathlib's
scope was `Mathlib/`. Flare selected 83 Lean files but excluded
`Tests/PublicAPI.lean` and `Tests/ProofAudit.lean` because they had no Lake module
ownership; these two files are not included in this gate's result. Flare's
changed-module phase was skipped because formatting changed no owned sources.
GraphQL's optional cache-download phase was skipped because the project has no
`cache` executable; its required builds completed.

Validation ran on macOS arm64 with eight logical CPUs and 16 GiB RAM. Mathlib's
first seven batches used one worker; validation resumed at batch eight with
automatic workers. The other projects used automatic workers throughout.
Parser integration was disabled. Recorded formatter-plus-diagnostics time was
8,643 seconds for Mathlib, 154 for CSLib, 28 for Flare, and 152 for GraphQL.
These are single-run batch totals with mixed worker settings, not comparative
benchmarks. Peak memory was not recorded.

The original local archive is `.scratch/release-performance/v0.4.8/` in the
maintainer's checkout. It contains `README.md`, `external.log`,
`automatic-workers.log`, `local.log`, `batch-timings.tsv`, and per-project source
manifests and batch logs. This tracked summary preserves the scope and outcome
without making those disposable files a documentation dependency.

## Local and CI validation

The v0.4.8 local gate passed the build, unit suites, development linter, fixture
checks, self-formatting diagnostics, and whitespace checks. Its
[CI run](https://github.com/duckki/leanfmt/actions/runs/44608136521) passed the
current-toolchain gate, previous-version compatibility suites, and macOS native
runtime checks.

The 1.0 preparation's local review gate passed on November 19, 2026: build and
full unit suite with warnings treated as errors, development lint, fixture dry
checks, self-formatting, final preservation/overflow/idempotency dry checks,
and `git diff --check`. Self-formatting used one worker and changed no sources;
fixtures have no drift. Local documentation links were checked as well.
`lake exe fmt --version` reports `leanfmt version 1.0.0 (Lean version 4.36.0)`.
Remote CI for the uncommitted preparation has not run.

## Upgrade

Once the release is tagged, pin `rev = "v1.0.0"` in the project's leanfmt Lake
dependency, run `lake update --keep-toolchain`, and check formatting and the
project build. The [stability policy](../stability.md) describes future output
changes and the supported toolchains.
